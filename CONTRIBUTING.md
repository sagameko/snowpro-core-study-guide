# Contributing to This SnowPro Core Study Guide

Thanks for considering a contribution. This repo is a community-friendly, unofficial study resource for the **SnowPro Core Certification (COF-C03)**, and it stays useful only if it stays current — Snowflake updates the platform (and occasionally the exam blueprint) faster than any single person can track.

## Ways to help

- **Fix errors.** Found a stale fact, a broken link, or a concept that's explained incorrectly? Open an issue or submit a correction.
- **Update for new exam versions.** When Snowflake ships the next exam revision (e.g., a future COF-C04), the domain weights and topic list in the root `README.md` and `STUDY_PLAN.md` will need a refresh.
- **Add practice questions.** More high-quality, original practice questions in each chapter's `QUESTIONS.md` are always welcome. Please write original questions — don't copy exam dumps or braindump content (see below).
- **Improve diagrams.** The SVG diagrams in each chapter's `images/` folder are intentionally simple. Clearer or more accurate versions are welcome.
- **Share resource links.** If you find a genuinely useful free or paid resource (course, blog, video series), suggest adding it to the resource list in the root `README.md`.

## Ground rules

1. **No exam dumps or leaked questions.** Sharing actual exam questions violates the Snowflake Certification Agreement and can get candidates' certifications revoked. Every practice question in this repo should be an original, concept-testing question written from public documentation.
2. **Cite your sources.** When adding or correcting technical content, link to the official Snowflake documentation (`docs.snowflake.com` or `learn.snowflake.com`) wherever possible.
3. **Keep the tone teaching-first.** This repo aims to explain concepts clearly, not just list facts to memorize.
4. **Match the existing structure.** Each chapter follows the same pattern: `README.md` (concept notes), `images/` (diagrams), `QUESTIONS.md` (practice + answer key). Please keep new content consistent with that layout.

## How to propose a change

Since this repo is distributed as a local file set rather than a live GitHub project, the simplest path is:

1. Note the file and section you want to change.
2. Draft your proposed edit.
3. Share it with the maintainer (see the root `README.md` for contact info) or, if this repo has been published to GitHub, open a pull request there.

No contribution is too small — a single fixed typo or a clearer sentence is genuinely appreciated.
